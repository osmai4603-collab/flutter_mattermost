# تحليل مكونات وتفاعلات صفحة الدردشة (Webapp)

تم تحليل مشروع الويب (`mattermost-webapp`) لفهم كيفية بناء وتفاعل واجهة الدردشة الأساسية، وذلك لتقديم مرجع عند تطوير أو تحسين تطبيق الـ Flutter.

## 1. المكونات الرئيسية لصفحة الدردشة (Chat Page Components)

تتوزع الواجهة في مشروع الويب إلى عدة أدوات (Components) محورية:

*   **الشريط الجانبي (Sidebar):**
    *   **الأداة:** `Sidebar`
    *   **الدور:** عرض قائمة القنوات والرسائل المباشرة والتبديل بين الفرق.
    *   **التفاعل:** عند اختيار قناة، يتم تحديث مسار الـ URL، مما يحفز إعادة بناء المكونات المركزية.

*   **رأس القناة (Channel Header):**
    *   **الأداة:** `ChannelHeader`
    *   **الدور:** عرض معلومات القناة الحالية (الاسم، الوصف) وأدوات البحث والوصول للأعضاء.

*   **عرض الرسائل (Message Stream):**
    *   **الأداة:** `PostView` -> `PostList`
    *   **الدور:** المسؤول عن عرض تدفق الرسائل. يستخدم `PostListVirtualized` لضمان أداء سلس مع القوائم الطويلة.
    *   **التفاعل:** يعتمد على البيانات القادمة من مخزن الحالة (Redux) ليعرض الرسائل الجديدة لحظياً.

*   **محرر الرسائل (Message Input):**
    *   **الأداة:** `AdvancedCreatePost` -> `AdvancedTextEditor`
    *   **الدور:** محرر نصوص متقدم يدعم التنسيق (Markdown)، الرموز التعبيرية، ورفع الملفات.
    *   **التفاعل:** يرسل البيانات للخادم ويحدث الحالة المحلية، ويتعامل مع الملفات عبر `FileUploadOverlay`.

*   **الجزء الجانبي الأيمن (Right Hand Side - RHS):**
    *   **الأداة:** `SidebarRight`
    *   **الدور:** عرض سلاسل الرسائل (Threads)، نتائج البحث، أو معلومات إضافية.

---

## 2. تفاعل الأدوات مع بعضها (Component Interaction)

تعتمد الهيكلية على الربط الوثيق بين الحالة (State) والاتصال اللحظي:

1.  **نظام التوجيه (Routing):** الرابط (URL) هو "مصدر الحقيقة" الأساسي. أي تغيير في المسار يؤدي لتحديث معرف القناة (`channelId`) في جميع المكونات عبر `ChannelIdentifierRouter`.
2.  **إدارة الحالة (Redux):** تشترك جميع المكونات في مخزن بيانات واحد. تحديث الرسائل في `AdvancedCreatePost` يظهر فوراً في `PostList` لأن كلاهما يراقب نفس الحالة في Redux.
3.  **الاتصال اللحظي (WebSockets):** يتم استقبال الأحداث (مثل "مستخدم يكتب..." أو "رسالة جديدة") وتحديث Redux مباشرة، مما يجعل الواجهة تتفاعل دون تدخل المستخدم.
4.  **تأخير الرندر (Deferred Rendering):** يتم استخدام `deferComponentRender` في `PostView` لتحسين الأداء المتصور (Perceived Performance) عبر تأخير عرض العناصر الثقيلة حتى تجهز الهيكلية الأساسية.
